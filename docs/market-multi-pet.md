> 市场 0.4.20：仅严格核对作品 ID、版本和角色 ID。市场使用仓库展示资料与宣传封面；安装后使用包内资料。名称、介绍及宣传封面无需与包内一致，继续保留图片格式和体积限制。

> 当前规则（市场 0.4.19 / 客户端 0.7.23）：索引无需 sha256；不校验作者是否替换附件，不比对历史哈希或历史文件大小。仍独立校验包内容、资源限制、作品 ID 和版本。历史哈希可保留为诊断数据。

# 一个仓库发布多个桌宠形象

一个公开 GitHub 仓库可以发布多个形象；每个形象拥有独立的资料、附件、版本、校验结果和市场卡片。同一形象的多个版本归入版本历史，市场列表显示其最新已上架版本。角色 ID（character.id）相同也不会合并不同的形象 ID（pet.id）。

## 生成仓库结构

从已导出的 `.petpack` 生成可投稿的目录：

```powershell
node scripts/build-pet-repository.mjs output/my-pets collection-v1 path/to/fox.petpack path/to/dragon.petpack
```

输出目录必须尚不存在。脚本读取并验证每个包，提取实际元数据与封面，计算 SHA-256，并复制 Release 附件；每次可包含 1–20 个不同的形象 ID。

```text
my-pets/
├─ lingpet-index.json
├─ pets/
│  ├─ snowfox/
│  │  ├─ pet.json
│  │  └─ previews/cover.png
│  └─ dragon/
│     ├─ pet.json
│     └─ previews/cover.png
└─ release-assets/                  # 仅用于上传 Release，被 .gitignore 排除
   ├─ snowfox-1.0.0.petpack
   └─ dragon-1.2.0.petpack
```

将索引和 pets 目录提交到公开仓库，在该提交创建正式 Release，并上传 release-assets 目录中的附件。最后只需在市场提交仓库链接。

## 索引协议

仓库根目录的 `lingpet-index.json` 使用以下结构：

```json
{
  "schemaVersion": 1,
  "pets": [
    {
      "id": "snowfox",
      "version": "1.0.0",
      "path": "pets/snowfox",
      "tag": "collection-v1",
      "assetName": "snowfox-1.0.0.petpack"
    },
    {
      "id": "dragon",
      "version": "1.2.0",
      "path": "pets/dragon",
      "tag": "dragon-v1.2.0",
      "assetName": "dragon-1.2.0.petpack"
    }
  ]
}
```

市场从最新正式 Release 标签读取索引。每项的 tag 可以分别指向不同的正式 Release；该形象的 pet.json 和 previews/cover.png 从该项 tag 对应的 path 读取，包从该 Release 的 assetName 读取。更新一款形象时只需更新对应资料、附件和索引项，其他项仍可引用旧标签。市场 0.4.21 起，有已上架作品的仓库每天自动发现更新，也可提交仓库链接手动入队。每个形象独立校验，相同附件或已知版本不会重复自动创建任务。

索引格式、条目数和重复的作品版本/附件映射在入队前检查；格式错误不会创建部分任务。作品字段、目录、元数据、封面和包内容分别在每个任务中校验。一款失败不影响其他款上架。重复提交返回已有任务；失败项允许重新提交或由管理员重试。

每个 path 必须是 pets/ 下的相对目录，不允许越界、反斜杠或 URL 参数。仓库与包内的作品 ID、版本、角色 ID 必须一致；名称、介绍、作者、授权及角色显示资料允许不同。市场展示以仓库资料为准，安装后的资料以分享包为准；格式版本与最低应用版本以包内值为准。仓库宣传封面可与包内封面不同，市场展示仓库封面。服务端逐包检查 ZIP 文件白名单、大小、PNG、八种动作、可选互动和候选动作，校验完删除临时下载，只保存展示预览、元数据、实际大小和哈希。

## 身份、展示与下载

- 形象身份：GitHub 数字仓库 ID + pet.id。名称或角色 ID 相同不导致合并。
- 版本身份：形象身份 + pet.version。允许作者替换同版本附件；发布独立新版本时使用新的版本号。
- 市场列表：每个形象一张卡片，展示最新已上架版本。下架、失败和待校验版本不显示。
- 历史接口：GET /api/versions/{记录编号}/history 返回该形象的已上架版本。
- 投稿响应：保留旧版 id、record、token（新记录时）字段，批量投稿新增 records、created、total；每条记录有独立编号和校验状态。
- 桌面客户端：保存每条投稿记录；不比对历史哈希及大小，始终执行包安全及身份校验。

每个来源 IP 每小时最多 10 次投稿请求；多包仓库最多 20 个待处理任务，全站最多 200 个。单包最高 200 MiB、解压合计 512 MiB、单文件 64 MiB，最多 163 个文件。

## 旧仓库兼容与升级

没有索引文件时，继续读取最新正式 Release 中唯一的 .petpack，以及同一标签下根目录 pet.json 和 previews/cover.png。只有明确的 GitHub 404 才认定索引不存在；权限、网络和索引格式错误不会静默回退。

旧投稿与数据库记录无需迁移，新增 work 字段可选。已上架旧记录保留；新投稿及重试任务使用完整包校验。需要升级市场后端及桌面客户端，获得批量投稿反馈及允许附件替换的安装行为。服务端继续向旧客户端返回首条记录以兼容单条响应。

## 默认展示作者（市场 0.4.25）

市场默认展示 GitHub 仓库所有者作为作者：优先使用已解析来源中的 Owner，旧记录从合法仓库地址提取账号或组织名。列表、详情、历史和安装信息统一在响应时应用该规则，既有投稿无需重打包或重新投稿。包内作者及已存档原始资料保留，不修改 GitHub 文件或附件；作者搜索同时匹配展示作者和原始资料作者。仓库 pet.json 可省略 author，校验时默认补入仓库所有者；分享包内 author 的格式校验继续保留。其他名称、介绍、宣传封面等展示规则不变。本体无需升级即可显示服务端返回的默认作者。
