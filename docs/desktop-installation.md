# 独立本体安装与 Agent 接入

0.7.0 起，新用户先安装灵伴本体，再从工作台的「Agent 接入」添加所需宿主。当前为 Windows 本机实现，不包含纯陪伴模式。

## 构建和安装

源码构建环境需要 Node.js ≥22.19、已安装的项目依赖、Electron 二进制，以及 Windows 自带 .NET Framework C# 编译器。执行：

```powershell
npm run build:desktop
```

构建产物目录包含 `LingPet-Setup-0.7.14.exe`、构建清单和 payload。安装程序携带 Electron、私有 Node、固定版本 pnpm 与内置 Claude 形象；终端用户无需另装 Node 或包管理器。首次安装不需要下载 Electron，市场、生成服务和宿主自身安装依赖可能需要网络。

0.7.11 安装界面可直接编辑安装目录或点击「浏览」选择其他磁盘；浏览时会在所选位置创建 LingPet 子目录。支持中文、空格和自定义文件夹名称。升级自动读取已有安装位置；更换位置需先卸载原安装。请选择独立程序文件夹，避免混入其他应用文件。

0.7.11 修复 Codex 已审核 Hooks 仍无法连接的问题：接入命令显式调用 PowerShell，并正确执行带空格的 Bridge 路径。旧用户升级本体后，需要在「Agent 接入」点击 Codex 的「更新接入」，重启 Codex，并审核更新后的 Hooks；随后新建会话发送消息验证。仅升级本体不会替换 Codex 已缓存的接入命令。

安装默认位于 `%LOCALAPPDATA%/Programs/LingPet`，首次安装的数据默认位于所选安装目录下的 `data` 子文件夹。本体提供桌面及开始菜单快捷方式，系统应用列表中有卸载入口。运行新版安装程序时，会通过本机认证接口正常退出当前灵伴，等待进程结束后再替换文件；最多等待 20 秒，退出失败时停止安装并提示手动退出。不会自动关闭 Agent 宿主，如 Bridge 文件被占用仍需退出相应宿主。新版本通过启动检查后激活，旧程序版本保留供回退，用户配置与内容不会放进版本程序文件夹。

安装器以 UTF-8 读取维护进程输出，安装失败时在 `%TEMP%/LingPet-Setup-Logs` 保存详细日志，并在提示中给出具体路径。如果自动退出未完成，请从托盘菜单退出灵伴后重试；关闭工作台窗口不会退出桌宠进程。

卸载由应用数据目录中的原生维护助手完成：先撤销并清理托管的 Agent 接入，再退出本体和删除程序目录。设置与形象数据保留；清理结果写入数据目录的 `uninstall.log`，失败详情写入 `maintenance-error.log`。

安装时只选择程序位置，数据和下载内容默认保存到安装目录下的 data 子文件夹。安装后可在「应用设置 → 常规 → 数据与内容目录」点击「修改目录」选择其他磁盘上的空文件夹。软件会复制设置、形象、下载内容、市场缓存、创作项目与运行缓存，保留原数据备份，再重新打开灵伴。正在进行的创作任务须先完成或取消。原有 0.7.0 安装升级沿用已有数据位置。

为保留 Agent 注册和已有素材路径，迁移后使用 Windows 目录联接维持原访问路径，实际内容保存在新目录；此操作不需要管理员权限。安装目录的 storage-move-result.json 记录迁移结果和原内容备份位置。迁移失败时保留原目录，并记录错误。

数据可以放在程序目录内的独立子文件夹，也可以放在其他磁盘；不能选择程序根目录、versions 等程序文件目录。卸载只移除程序文件，内置数据子目录和外部数据目录都会保留，含数据的安装父目录也会保留。安装记录保存在程序目录的 desktop-location.json，轻量插件入口会自动读取它。

当前构建未配置代码签名；`release.json` 明确记录 codeSigned=false。文件摘要用于完整性检查，不代表发行者身份认证。不要将此开发构建当成已经签名的正式发行包。

## 在本体中安装插件

1. 打开工作台的「Agent 接入」，选择 Codex、Cursor 或 DSH。
2. DSH 默认自动查找本机命令，使用 DSH_HOME（未设置时为用户目录下的 .dsh）和 web profile，直接点击安装即可。多套 DSH 环境可展开「高级选项」指定命令、配置目录和 profile；未检测到 DSH 时会提示先安装宿主。
3. Codex 同样自动查找命令，使用 CODEX_HOME（未设置时为用户目录下的 .codex），无需手动填写参数。多套环境可展开高级选项，命令支持 exe、cmd、bat。未找到命令时需先安装 Codex CLI 或指定已有命令位置。Cursor 可检查自动填入的配置目录。本体会提供私有 Node 给 npm 的 cmd 启动器。
4. 点击「安装接入插件」。界面显示计划步骤，操作记录和配置备份保存在 integrations/transactions。
5. DSH 安装完成后请重启 DSH，再发送一条消息验证接入。其他宿主根据提示启用插件、审核 Hooks 或重新加载。发送一条真实消息后，接入页才显示收到真实事件。

Codex 通过本机 CLI 注册轻量本地市场并安装插件，Hooks 和 MCP 都使用稳定 Bridge 入口。安装完成后会弹出步骤说明，需要点击「我知道了」关闭。请完全退出并重新打开 Codex，在对话框下方查看灵伴 Hooks 审核提示，审核后选择允许；确认插件已启用，再新建会话并发送消息验证连接。Hooks 信任审核由用户在宿主完成。

Cursor 默认无需填写参数：选择 Cursor 后直接点击「安装接入插件」，自动使用用户目录下的 `.cursor`。自定义配置目录仅在「高级选项」中选择，不需要指定 Cursor 命令文件或 profile。安装后重新加载 Cursor 窗口（或退出后重新打开），新建 Agent 会话并发送消息验证连接。

Cursor 合并用户 Hooks 和独立命名的 MCP 入口，保留其他配置；事件和管理/创作工具均来自本体。首版不自动安装旧 VSIX 侧边栏，可通过 MCP 管理入口或桌宠右键打开工作台。

DSH 将轻量插件安装到所选 DSH_HOME 和 profile；插件监听宿主事件并转发本体，创作工具代理到本体。profile 安装可能由 DSH/pnpm 下载其依赖。

DSH 安装优先使用系统 PATH 中的 pnpm，避免覆盖现有 profile 使用的 pnpm 主版本和存储格式；系统没有 pnpm 时才使用本体携带的版本。安装失败时界面保留 pnpm 的标准输出及错误输出，包括依赖存储冲突和仓库连接错误。

「检查」验证接入包和可检查的宿主注册；不会把包存在当成 Hooks 已信任或真实事件已验证。「重新安装接入」补回接入文件并重新注册，保留旧包；已安装的接入版本低于本体携带的版本时，按钮显示「更新接入」。这些操作只针对接入插件，不升级 Agent 宿主或灵伴本体。「卸载接入」先撤销权限，再移除属于灵伴的注册，不影响其他接入或形象。

## 运行与退出

本体承载会话观察、跟随和所有桌宠。关闭工作台不退出本体；宿主内的「关闭全部桌宠」只隐藏桌宠，不关闭事件服务。从托盘退出本体后，Hook 快速中性返回，不下载、安装或重新拉起本体。

本体升级使用独立安装程序，不再从 Agent 插件覆盖共享运行时；工作台会提示此维护方式。旧发布脚本仍保留用于历史包兼容，不作为新用户安装入口。

## 旧版迁移边界

既有数据目录继续使用，桌宠设置和形象不重置。安装接入时会替换可识别的旧 Cursor 用户 Hook。旧完整 Codex/DSH 插件及 Cursor VSIX 尚须检查并卸载或停用，再重启对应宿主；本次实现不会扫描后擅自清空未知插件目录或信任记录。

不要同时启用旧完整插件和新轻量插件。新本体拒绝插件端本体更新请求，但旧插件本身可能仍启动自己的旧进程，因此未解除旧接入时不能宣称迁移完成。

## 验证

```powershell
npm run test:desktop-first
npm test
node scripts/test-desktop-first.mjs <构建产物>/payload
```

隔离测试在项目 `.test-data-desktop-first-smoke` 中安装本体，不创建系统快捷方式或更改日常 Agent 配置，并从子进程 PATH 移除系统 Node。测试稳定入口、启动检查、真实 Hook 子进程投递、MCP 初始化、本体退出后不再唤起，以及配置保留。

受限执行环境若无法以默认 Chromium 沙箱启动 Electron，可显式在测试命令末尾加 `--no-sandbox`。这只用于诊断和隔离自动测试，不改变安装程序和普通启动的默认沙箱；这种测试不能替代正常 Windows 桌面的默认沙箱验收。

0.7.13 修复升级时 Agent 仍占用 LingPetBridge.exe 导致的 EPERM：内容相同的入口不重复替换；需更新的旧入口先移入维护目录，再发布新入口，现有 Agent 连接可以继续运行。升级失败时同时恢复入口文件与版本记录。仍在运行的旧入口暂留于维护目录，由卸载流程一并清理。

0.7.14 修复 Codex 更新接入时同名市场来源冲突：更新、重装和部分失败后重试会查询宿主实际注册的来源，再迁移对应灵伴市场。安装失败时尝试恢复原市场和插件缓存，其他市场保持不变。旧接入更新失败的用户安装新版后，可直接点击「重新安装接入」恢复，无需手动删除市场。
