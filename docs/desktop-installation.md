# Windows 安装、数据目录与 Agent 接入

第一次使用请先阅读 [快速开始](getting-started.md)。本文补充安装位置、接入管理、升级与数据迁移。

## 安装桌面版

当前支持 Windows x64 本机环境。从 [GitHub Releases](https://github.com/fourzkw/lingpet/releases/latest) 下载 `LingPet-Setup-<版本号>.exe`，运行后按提示安装。

安装包包含 Electron、私有 Node.js、备用 pnpm 和内置 Claude 像素形象。普通用户无需为灵伴另装 Node.js 或包管理器，首次启动无需下载 Electron。市场、生成服务及宿主安装依赖可能需要网络；宿主自身的运行要求由宿主决定。

默认程序位置为 `%LOCALAPPDATA%/Programs/LingPet`。安装界面支持输入路径或浏览选择其他磁盘，路径可包含中文和空格。请选择独立的程序文件夹，避免混入其他应用文件。安装后可从桌面和开始菜单打开灵伴，也可在 Windows 应用列表中找到卸载入口。

首次安装默认「不跟随会话」，可直接显示桌宠、互动和试映动作，无需先接入 Agent，也无需模型 API Key。

当前构建未配置代码签名，构建清单 `release.json` 记录 `codeSigned=false`。SHA-256 摘要用于核对文件完整性，不代表发行者身份认证。

## Agent 接入与更新

在工作台「Agent 接入」选择所需宿主，点击「安装接入插件」。默认自动检测本机环境，多套环境可展开高级选项。

| 宿主 | 检测和配置 | 安装后验证 |
| --- | --- | --- |
| Codex | 自动查找本机 CLI；使用 `CODEX_HOME`，未设置时使用用户目录下的 `.codex`。未找到命令时需先安装 Codex CLI 或指定已有命令位置。 | 完全退出并重开，确认插件启用，按提示审核 Hooks，新建会话发送消息。 |
| Cursor | 默认使用用户目录下的 `.cursor`；高级选项可选择自定义配置目录，无需指定命令或 profile。 | 重新加载窗口或重开，再新建 Agent 会话发送消息。 |
| DSH | 自动查找命令；使用 `DSH_HOME`，未设置时使用用户目录下的 `.dsh`，默认 web profile。高级选项可选择命令、配置目录和 profile。 | 确认对应正在使用的实例，重启后发送消息。 |

灵伴为自己的 Hook 和 MCP 入口提供私有 Node。DSH 优先使用已有系统 pnpm，未找到时使用安装包携带的版本；宿主安装命令可能联网下载依赖。

安装完成弹窗保留后续操作说明，阅读后点击「我知道了」。完成重启、启用或审核后，务必在真实会话中发送消息，并在接入页确认已收到事件；「已安装」或管理通道连接不能代替这一步。

选择桌宠，在「跟随」页设置对应来源、所有来源或固定会话。首次接入及手动安装接入可能将当前符合条件的桌宠从「不跟随会话」切换到对应来源；已有跟随规则继续保留。手动选择「不跟随会话」后，重连、重启和接入自动更新不会自行恢复跟随。

### 修复、更新与卸载接入

- 「检查」验证接入文件和可检查的宿主注册，不代表 Hooks 已审核或事件已接通。
- 「更新接入」应用随本体携带的接入更新；「重新安装接入」可修复文件或注册缺失。操作后仍需按提示重载宿主或审核 Hooks。
- 「卸载接入」撤销并清理灵伴拥有的接入，不卸载宿主，也不删除桌宠和形象。
- 安装失败时先查看页面错误；操作记录与配置备份位于数据目录的 `integrations/transactions`。无需先删除全部配置。

本体与各接入独立管理版本。Windows 安装版启动后会后台检查已安装且启用的托管接入，只在接入内容需要更新时应用新版本；未安装、已停用或安装未完成的接入不会自动安装。

自动更新不会代替宿主重载和 Hooks 信任审核。更新失败时保留原接入记录与旧包，可在接入页手动重试；同一失败版本不会每次启动反复自动尝试。

## 升级桌面版

下载更高版本的 `LingPet-Setup-<版本号>.exe`，运行安装程序。升级会沿用已有安装位置和数据位置，保留设置、形象与创作项目。

建议先从系统托盘退出灵伴。安装程序也会尝试通过本机接口正常退出旧进程，最多等待 20 秒；退出失败时停止安装并提示手动退出。安装程序不会自动关闭 Agent 宿主，若提示文件占用，请关闭相关宿主后重试。

新版本通过启动检查后激活，旧程序版本保留供回退。更换程序安装位置需先卸载原安装，再安装到新位置；移动内容数据请使用下节的数据迁移功能。

安装失败日志位于 `%TEMP%/LingPet-Setup-Logs`，具体路径会在失败提示中给出。关闭工作台窗口不会退出后台，请通过托盘完全退出后重试。

## 数据与内容目录

首次安装的数据默认保存到程序目录下的 `data` 子文件夹，已有安装升级沿用原数据位置。

在「应用设置 → 常规 → 数据与内容目录」可查看当前位置，点击「修改目录」选择其他磁盘上的空文件夹。正在进行的创作任务需先完成或取消。

迁移会复制设置、形象、下载内容、市场缓存、创作项目和运行缓存，保留原数据备份后重新打开灵伴。迁移后通过 Windows 目录联接保留原访问路径，维持已有接入和素材引用；失败时保留原目录并记录错误。安装目录中的 `storage-move-result.json` 记录迁移结果与备份位置。

数据可放在程序目录内的独立子文件夹或其他磁盘，不能选择程序根目录、`versions` 等程序文件目录。卸载默认保留内置或外部数据目录。卸载步骤见 [卸载与重装](uninstall-and-reinstall.md)。

## 从旧版完整插件迁移

如果曾安装携带完整运行时的 Codex/DSH 插件或 Cursor VSIX，请先在对应宿主中停用或卸载旧插件，再安装桌面版并从「Agent 接入」添加轻量接入，完成后重启宿主。

安装接入会替换可识别的旧 Cursor 用户 Hook，但不会清空未知插件目录或信任记录。请检查是否仍有旧完整插件启用，避免多个旧进程同时运行。已有数据位置和素材应先确认并备份，迁移后再验证形象与跟随设置。

## 开发者构建与验证

以下命令只供源码开发和发布验证使用，普通用户按本文安装桌面版即可。

构建需要 Windows、Node.js ≥22.19、项目依赖、可用的 Electron 二进制及 Windows .NET Framework C# 编译器。源码准备见 [README](../README.md#从源码运行)。

```powershell
npm run build:desktop
```

产物位于 `artifacts/` 下新建的构建目录，包含 `LingPet-Setup-<版本号>.exe`、`release.json` 和 `payload`。

```powershell
npm run test:desktop-first
npm test
node scripts/test-desktop-first.mjs <构建产物>/payload
```

隔离测试不修改日常 Agent 配置，并会从子进程 PATH 移除系统 Node，验证安装包自带环境。受限环境中可按测试脚本支持使用 `--no-sandbox` 诊断，但不能代替正常 Windows 桌面的默认沙箱验收。发布内容与验证规则见 [发布打包说明](release-packaging.md)。
