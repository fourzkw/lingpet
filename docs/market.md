> 市场 0.4.20：仅严格核对作品 ID、版本和角色 ID。市场使用仓库展示资料与宣传封面；安装后使用包内资料。名称、介绍及宣传封面无需与包内一致，继续保留图片格式和体积限制。

> 当前规则（市场 0.4.19 / 客户端 0.7.23）：索引无需 sha256；不校验作者是否替换附件，不比对历史哈希或历史文件大小。仍独立校验包内容、资源限制、作品 ID 和版本。历史哈希可保留为诊断数据。

# 灵伴集市

投稿和查询均只需 GitHub 仓库链接。市场 0.4.21 起，有已上架作品的仓库每天自动发现新版本并排队校验；作者也可用同一链接手动提交入队，无需等待每日检查。通过后上架，不会自动更新用户本地已安装的桌宠。

桌面端 0.5.0 的「已安装与版本」会按作者仓库及作品 ID 检查已上架的新版本，下载仅加入形象库，旧版本保留；选择版本可切换／回退当前桌宠。离线时仍可使用已安装版本。相同素材的不同版本可共用文件并保留版本记录。

分享包仍要求八种会话状态，可在 `manifest.clips` 附带单次播放的 `click`、`pet`，路径为 `sprites/click.png`、`sprites/pet.png`，原图使用 `original/` 前缀，清单尺寸与状态动作一致。含互动的包声明 `minAppVersion: "0.5.0"`，导入与再次导出保留互动。市场服务器需同步升级兼容校验后才能校验这一最低版本的投稿。

市场逐包校验作品资料、封面、动作和资源格式，通过后独立上架。新校验记录保存包哈希和大小，客户端安装时校验包格式及作品身份；历史无哈希记录保留兼容。多形象仓库格式与生成脚本见 [多形象仓库协议](market-multi-pet.md)。

工作台侧边栏「桌宠市场」是内置市场页面，可搜索上架后的作品、查看封面、查看封面和作品介绍，选择新增一只桌宠、应用到当前桌宠或仅加入形象库。客户端从作者的 GitHub Release 下载 `.petpack`，通过包格式、路径、资源大小和作品 ID、版本检查后安装，不比对历史附件哈希和大小，仍执行包安全及身份校验。应用到当前桌宠会保留其位置和跟随设置。已安装素材可离线播放；网站未部署或不可用时仍可导入本地分享包。

作者在「更多操作 → 导出分享包」填写作品 ID、名称、版本、作者和授权声明，将生成的文件上传自己公开 GitHub 仓库的正式 Release，然后在工作台「桌宠市场 → 投稿作品」或网页市场免登录投稿，只需填写 GitHub 仓库链接。多形象仓库使用 lingpet-index.json 为各形象绑定资料路径、Release 标签和附件；无索引时继续读取最新正式 Release 的唯一 .petpack 与根目录资料。查询同样只需仓库链接，可查看各版本的公开状态和校验结果，无需编号或凭证。每个版本独立校验，通过后自动上架，同一作品发布更新需增加版本号。请只发布有权分发的作品；创作项目、提示词、密钥和本机设置不会进入分享包。

管理员使用独立账号密码登录后台，可查看作品资料和校验结果、重试失败投稿或下架作品。服务器保留版本和操作记录；大文件由作者托管。新投稿逐包下载并校验，删除临时包，只保存数据库与展示预览快照；历史投稿的动作预览继续可用。GitHub 上的公开附件可在市场之外访问。

默认市场地址为 `https://lingpet.fourzkw.top`。服务器使用 Go、bbolt、systemd 和 Nginx，无需 Docker。源代码中的 `market/README.md` 包含 DNS、管理员密码配置、部署、备份与限制说明，无需注册 GitHub OAuth App。Linux amd64（x86_64）的独立部署包包含二进制及配置模板；服务器无需安装 Go。

市场按独立形象展示最新已上架版本，提供版本历史接口。GitHub 附件删除后会导致下载失败；作者可以替换附件，客户端安装当前附件并校验包格式、资源限制与作品 ID、版本。市场展示信息与预览保持校验通过时的快照，更新展示内容需重新投稿校验。
个人和组织仓库均可推荐，提交链接不代表作者身份，作品来源和授权由提交者如实填写。市场服务版本独立为0.4.19。旧客户端可继续使用首条投稿响应；允许附件替换的安装行为需使用0.7.23及以上客户端。旧投稿也可使用仓库链接查询，撤回需联系管理员。



首次部署默认账号为 admin，服务自动生成本次部署专属的初始密码，保存在数据目录的 initial-admin-password.txt。首次登录必须改密；修改完成后初始文件会删除。密码哈希保存在 market.db，更新程序时保留数据目录即可继续使用原密码。账号和可选密码哈希环境变量只用于首次初始化；从旧版升级会导入原配置中的密码哈希。


管理员可通过网页右上角「修改用户名」更换登录名，需验证当前密码；新用户名不含空白，最多64个字符。更名后密码保持不变、其他旧会话失效，当前会话继续使用。后续重启和升级保留数据目录即可保留新用户名，首次初始化的用户名环境变量不会覆盖数据库。



管理后台包含数据概览、校验队列、作品管理、客户端下载和操作记录。Windows 桌面安装程序发布至 fourzkw/lingpet 的 GitHub Release；官网与桌面端的下载入口会直接解析到最新 Release 的安装包文件，浏览器点击后立即开始下载，不再打开 Release 页面。服务端只解析资产地址，不中转、不存储安装包，文件流量仍由 GitHub 承担。

下载入口的解析来源是 Release 附件中同时上传的 `release.json`（字段 `version`、`setup`、`sha256`、`bytes`）与 `LingPet-Setup-<版本号>.exe`。`GET /api/downloads` 返回 `desktop` 对象（版本、文件名、大小、sha256、发布日期与 Release 说明）；`GET /downloads/desktop` 302 到对应的 GitHub 资产文件。解析结果缓存 15 分钟，刷新失败时沿用上次结果；缺少安装程序或 `release.json` 时退回跳转最新 Release 页面。官网只统计下载入口点击，不代表文件下载完成。


桌面客户端0.4.4新增面板内「发现桌宠、投稿作品、查询投稿」页面。动作预览使用服务端缩小后的图集，不操作真实桌宠；安装时使用完整素材。选择左侧桌宠或「返回工作台」可回到外观与跟随设置。默认新增实例，也可应用到当前实例或只加入形象库。本机投稿记录仍保存在 market-receipts.json（最多100条），网页保留最近50条记录，均可点击仓库记录查询。仓库链接投稿和查询需要同步升级市场服务端及桌面客户端；服务端继续兼容旧版投稿及凭证查询。


连接设置支持明确指定 HTTP 或 HTTPS 根地址。默认地址使用 HTTPS；当前服务器的 HTTP 地址为 http://lingpet.fourzkw.top，HTTPS 证书域名需要与站点匹配。若使用当前 HTTP 站点，可在「连接设置」输入该 HTTP 根地址。不会自动跳过证书校验或在请求失败时降级连接。


## 旧单形象仓库兼容

公开仓库同一 Release 标签下必须包含 pet.json（作品 ID、版本、名称、作者、授权和介绍，格式与分享包元数据相同）及 previews/cover.png（8bit RGBA PNG，最多1 MiB、1024×1024像素总量）。服务从 GitHub API 获取展示资料与附件信息，并下载 .petpack 进行完整校验；通过后保存展示预览与大小，删除临时下载。客户端从 GitHub 下载并校验包格式与作品身份；失败投稿可重试。


## GitHub 访问加速

桌面客户端安装资源包时依次尝试 GitHub 直连、`https://gh-proxy.com/`、`https://ghfast.top/`，无需配置本地代理。直连成功后不访问备用线路；连接失败、HTTP 错误、传输中断或资源包校验失败时自动切换。下载进度显示当前线路；单次连接等待响应最多20秒，每条线路包含重定向和传输最多180秒。第三方线路可能暂不可用，全部失败时显示各线路的错误，并可从 GitHub Release 手动下载 `.petpack` 后导入。

备用线路仅下载公开 GitHub 附件，不发送令牌或本机配置。客户端限制 HTTPS 下载目标、重定向次数和资源包体积，并在安装前校验包格式、作品 ID 与版本。市场 API 仍访问连接设置中的市场地址；市场服务不可达时，资源包备用线路不能替代市场服务。

默认依次尝试 direct（GitHub 直连）、gh-proxy（https://gh-proxy.com/）、ghfast（https://ghfast.top/），无需安装本地代理。每条线路单次请求最多20秒，返回网络错误、非成功状态或无效 JSON 后尝试下一条；直连 GitHub 返回404时直接提示缺少仓库、标签或文件。第三方服务对 API 的支持和可用性可能变化，所有线路失败时保留明确错误，可在后台重试。

可在 /etc/lingpet-market.env 设置 LINGPET_GITHUB_ROUTES=gh-proxy,direct,ghfast 调整顺序；设置为 direct 关闭中转。保存后执行 sudo systemctl restart lingpet-market。默认不配置也生效。GITHUB_TOKEN 仅发送给直连 GitHub API，中转不携带认证信息；限制 HTTPS、公网目标和已知重定向域名，保留响应体积限制。从服务端 0.4.29 起，资料读取与完整分享包下载均使用上述线路。附件逐线路串行流式下载，每条线路含重定向与传输最多180秒；连接失败、HTTP 错误、网页响应、传输中断或实际大小不符时尝试下一条，并清理本次未完成文件。全部失败时显示各线路错误。仍限制重定向域名、体积和包内容，不克隆仓库，也不增加校验并发。


客户端0.4.5修复轻量投稿缺少审核哈希时无法安装的问题，并在作品详情提供 GitHub 仓库和对应 Release 入口。使用旧客户端遇到“无效审核记录”时需更新客户端并完全退出后重新启动；仅更新服务端不能移除旧客户端的强制校验。市场服务0.4.10在审核列表和作品详情提供仓库及 Release 链接。


客户端0.4.7按完整动作素材及播放配置识别重复形象：同一形象从本地导入后再从市场安装会复用已有记录，作者、授权、介绍或ZIP压缩变化不会新增相同形象。历史重复记录在形象库中合并展示并迁移实例引用，保留原素材和创作项目；同名但动作素材或时序不同的形象不合并。


网页与桌面市场的每个线上桌宠卡片及详情均展示下载量和 Star。下载量为同一桌宠所有已上架版本对应 Release 分享包附件的 GitHub 下载次数之和（同一附件去重），Star 为作者 GitHub 仓库的获星数。服务端缓存15分钟；读取失败时保留上次成功数据，1分钟后允许重试，无历史数据时显示“暂不可用”。旧服务端没有统计字段时客户端同样显示“暂不可用”。

## 分享包的角色归属

新导出的 pet.json 包含 character 对象（id、name、description），manifest.json 的 character 保存同一角色 ID。作品 ID 标识形象包，角色 ID 标识该形象所属角色；例如 lingpet-chatgpt-dragon 和 lingpet-chatgpt-white-dragon-h3 的角色 ID 均为 chatgpt，导入后归入 ChatGPT 的形象列表。内置角色使用内置 ID；社区角色按发布来源与角色 ID 分组，同名角色不会因此合并。导入后再导出会保留角色资料。

旧官方形象包按固定作品 ID 恢复角色归属：lingpet-chatgpt-dragon 与 lingpet-chatgpt-white-dragon-h3 同属 chatgpt，lingpet-deepseek-h3 属于 deepseek。启动读取已有形象库以及导入原始旧包时均执行此兼容处理，无需重新导入或重新下载。其他没有 character 对象的旧包仍创建独立社区角色，不根据显示名称合并。桌宠实例会同步到恢复后的角色，保留位置、形象、显示版本和跟随设置；读取兼容处理保留原始形象记录。本地可编辑创作的角色归属不会被市场包覆盖。

## 市场排序与筛选（服务端 0.4.24 / 桌面端 0.7.24）

网页和桌面端发现页支持最近更新、累计下载量、仓库 Star、名称顺序、包体积从小到大排序；支持含原图、含像素、两者都有，以及点击、摸头、任一或两种互动、近 7/30/90 天更新的组合筛选。下载量按同一桌宠所有已上架版本附件累加，同一附件只计一次，Star 按仓库计数，同仓库不同形象共享仓库 Star；没有统计的数据排在已知数据之后，同值以更新时间、记录 ID 稳定排序。名称按不区分大小写的字符顺序排列，包大小以市场校验时记录为准。

GET /api/pets 继续返回数组，兼容旧客户端；新增参数 sort=updated|downloads|stars|name|size、style=original|pixel|both、interaction=any|click|pet|both、recent=7|30|90；空值代表不限。q 搜索作品名称、简介、作者、作品 ID、角色资料及仓库。非法筛选值返回 400。先取每个形象最新已上架版本，再筛选与排序，最多返回 200 项，历史版本不会因为更符合筛选而重新出现。网页条件保存在 URL，可刷新或分享；提供重置筛选和空结果重置。统计继续复用既有缓存。
## 默认展示作者（市场 0.4.25）

市场默认展示 GitHub 仓库所有者作为作者：优先使用已解析来源中的 Owner，旧记录从合法仓库地址提取账号或组织名。列表、详情、历史和安装信息统一在响应时应用该规则，既有投稿无需重打包或重新投稿。包内作者及已存档原始资料保留，不修改 GitHub 文件或附件；作者搜索同时匹配展示作者和原始资料作者。仓库 pet.json 可省略 author，校验时默认补入仓库所有者；分享包内 author 的格式校验继续保留。其他名称、介绍、宣传封面等展示规则不变。本体无需升级即可显示服务端返回的默认作者。
## 同版本资料刷新（市场 0.4.28 / 桌面端 0.7.29）

每日来源检查会比较已上架版本的名称、简介、作者、授权、角色资料与封面；发现变化后加入现有串行校验队列。作者也可以再次提交同一仓库，立即创建资料刷新任务，无需增加作品版本号。同一作品同时只保留一个待处理刷新任务；资料未变化时跳过分享包下载。管理员可在校验队列中查看“资料刷新”任务，投稿查询会显示完成或失败原因。

刷新期间旧资料继续上架；校验通过后保留作品链接与版本记录，切换资料和封面，校验失败则保留原内容。已下架作品不会被刷新任务重新上架。资料变动时仍需完整校验分享包；作品 ID、版本以及仓库与包内的角色 ID 必须一致，名称、介绍等展示字段可以不同，以仓库资料为准；市场作者仍默认显示仓库所有者。更改角色归属时，请同步修改包内角色信息。资料指纹仅用于判断是否需要刷新，不用于锁定附件或核对作者是否替换附件。

资料读取自索引指定 Release 标签对应的提交（单作品仓库同样读取其 Release 标签），只修改默认分支不会更新旧标签资料。可让索引指向包含新资料的新 Release 标签，作品版本保持不变，再手动提交或等待每日检查。若直接更新既有标签指向，也会在下次检查时比较资料。新版本与资料刷新共用一个工作线程，每个任务后间隔 10 秒；自动任务最多占 180 个待处理名额，总队列最多 200 个。每日检查在校验队列空闲时执行，到期时间不是保证执行时间。

市场刷新不会自动覆盖用户本地已经安装的同版本包；本地形象库仍保留原版本。桌面端重新加载市场列表或详情后，会根据资料修订刷新封面缓存。
