# 多桌宠与共享安装（0.2.0）

DSH 插件、Cursor 原生插件/侧边栏各自携带完整桌宠组件，任意入口都可以独立准备运行环境，不需要安装另一个宿主。双方同时启用时，共用 `%LOCALAPPDATA%/BoardAiPet` 中的一套后台服务和一份桌宠配置；不会自动给另一个应用安装插件。

## 使用

0.2.1 工作台左侧常驻“桌宠列表”，显示每只桌宠的形象、跟随规则和显示/暂停状态。点击一行切换当前编辑对象，行内按钮独立暂停/启用，列表下方可新增桌宠；右侧保留复制、删除、改名与详细设置。

打开工作台，在左侧“我的桌宠”选择当前编辑对象。新增或复制后可分别设置名称、四种角色形象、大小、置顶、显示标签和跟随规则。右键某只桌宠会弹出快捷控制，选择“打开工作台”才进入完整设置。拖动位置、隐藏、暂停和动作试映都只作用于当前桌宠。

| 跟随规则 | 行为 |
| --- | --- |
| 全局自动跟随 | 在所有来源中优先等待批准/输入，再选择最近活动会话 |
| DSH 自动跟随 | 只在 DSH 会话中选择，不会转到 Cursor |
| Cursor 自动跟随 | 只在 Cursor 会话中选择，不会转到 DSH |
| 指定会话 | 先选择此模式，再点击下方会话；断线后保留绑定等待恢复 |

来源筛选只用于查找会话；“跟随规则”才决定这只桌宠实际跟随哪里。多只桌宠可以绑定同一会话。固定绑定遇到身份歧义时提示重新选择，绝不自动跟随另一个任务。

工作台“启用当前桌宠”和两个宿主管理页中的“暂停”只控制一个窗口。全局“退出全部桌宠”才会结束后台服务并暂停双方自动唤起，显式“启动桌宠服务”恢复。删除所有桌宠也不会删除接入器或关闭管理服务，可继续新增。

## 安装与升级

- DSH：安装 `artifacts/dsh-board-pet-0.2.0.tgz`。匹配运行 profile；Web 设置页提供共享服务控制与独立桌宠启停。
- Cursor：安装 `artifacts/board-pet-sidebar-0.2.0.vsix`，必要时执行 Developer: Reload Window。侧边栏提供服务启停和独立桌宠管理，完整外观与会话绑定在工作台编辑。
- 命令行：项目目录 `node bin/board-pet.js settings`；支持原有 start / doctor。

第一次升级自动将旧 settings.json 迁移为 schemaVersion 2，保留默认桌宠的形象、大小、位置和显示偏好，并在旁边保存 v1-backup。不要用旧版直接编辑新配置。

## 共享运行时

运行时安装在数据目录 `shared/releases/<版本>-<摘要>/`，active.json 指向当前版本。准备期间使用进程安装锁，完成复制与摘要校验后原子切换；Electron 可执行文件及依赖也复制到该目录，所以卸载任一宿主包不会破坏其他宿主使用的后台程序。

较旧包不降级当前版本。同版本、同内容直接复用；同版本却不同内容时保留已安装版本，应提升版本号后发布。协议不兼容则拒绝。升级保留上一版，启动守护进程在新版无法运行时恢复上一版，并隔离故障摘要，阻止另一个接入器反复装回故障版本。未成功安装过任何版本的首次启动没有可回退版本。

退出一个宿主只注销其来源，不退出共享服务。Cursor 扩展窗口通过租约维持接入；关闭/停用最后一个启用扩展的 Cursor 窗口后，Cursor 桥接会结束，DSH 不受影响。单独安装原生 Hooks 而没有侧边栏时保留原生接入方式。未来若需要清理公共运行时，应提供单独的明确清理操作；本次不自动删除公共配置或旧版本。

## 会话身份

临时 instanceId 用于连接与事件排序，scopeId + source + sessionId 用于桌宠的固定绑定。Cursor 使用本用户共享桥接范围；DSH 使用工作目录与 profile 派生的范围，也可通过 sourceId 显式区分同一路径的自定义宿主。旧接入器缺少稳定 scopeId 时仍兼容接收，但固定绑定跨该旧接入器重启的恢复能力取决于其身份是否变化，建议两边都升级到 0.2.0。

## 验证

`npm test`、`npm run check`、`npm run test:dsh`。真实桌面测试：`node scripts/test-shared-runtime-live.mjs`（并发启动与恢复）、`node scripts/test-desktop-hot.mjs`（热更新及故障回退）。多窗口渲染测试通过 BOARD_PET_MULTI_SMOKE 测试入口运行，结果保存在 artifacts/multi-pet-smoke。
