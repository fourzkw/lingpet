# 安装与接入检查

适用 Windows 本机桌宠。桌宠包版本以根目录 package.json 为准，网站服务单独发布。请下载与你使用的宿主对应的包；不必安装其他宿主，也不必先构建源码。

## 1. 检查环境

- 在 PowerShell 执行 `node --version`，需要 Node.js 22.19 或更高版本。若找不到命令，安装 Node.js 并确认加入 PATH，然后完全退出并重启宿主。
- 宿主与桌宠需在同一台 Windows 电脑、同一用户下运行。远程、容器、WSL 到 Windows 桌面的连接暂不支持。
- 内置形象和状态跟随不需要模型 API Key。默认发布包不携带 Electron 二进制，首次启动需要联网下载并校验，之后复用本地缓存。网络代理必须指向仍在运行的服务。

## 2. 选择一种安装方式

| 宿主 | 发布包 | 安装及启动 |
| --- | --- | --- |
| DSH | `.tgz` | 在运行中 DSH 的插件管理页安装并启用，确认 profile 与当前实例一致，再打开桌宠工作台。Desktop 用户优先从应用内安装。 |
| Cursor | `.vsix` | 扩展面板菜单选择「从 VSIX 安装」，运行 `Developer: Reload Window`，在「灵伴桌宠」侧边栏启动桌宠、打开工作台。 |
| Codex | `.zip` 本地插件市场 | 解压到固定目录并添加市场，安装 board-pet，启用插件并审核八项 Hooks，然后重启本地宿主。具体命令见 [Codex 接入](codex-integration.md)。 |

源码开发及其他安装方式见 [README](../README.md)、[Cursor 接入说明](cursor-integration.md)。Codex 包的运行时目录为 `plugins/board-pet/runtime`，原生 Cursor 插件为 `runtime`；下文命令均在包含 `bin/board-pet.js` 的目录执行，DSH 在已安装插件目录执行。

## 3. 显示伙伴并选择跟随来源

尚未接入任何 Agent 时，工作台显示「让伙伴跟上你的第一次会话」按钮，点击进入「Agent 接入」。安装任意接入插件后按钮隐藏，宿主暂时离线也不会再次显示。DSH、Cursor 和 Codex 的连接状态与排查说明统一在「Agent 接入」查看。如果没有桌宠，先点击左侧「新增桌宠」，再选择桌宠并点击「显示到桌面」。跟随规则在桌宠的「跟随」设置中调整。

角色外观与宿主来源独立，任一内置角色均可跟随所选宿主。

## 4. 验证真实会话

结束动作试映，在所选宿主新建 Agent 会话并发送一条消息。在「Agent 接入 → 连接状态」确认对应宿主显示「已连接，已收到会话事件」。仅管理通道连接或动作试映不代表已收到真实会话事件。DSH 安装完成后需重启 DSH。Codex 安装完成后需完全退出并重新打开，在对话框下方审核并允许灵伴 Hooks，再新建会话发送消息。安装成功后会保留步骤弹窗，点击「我知道了」关闭。

收到会话事件说明 Agent 接入已生效；如果伙伴仍未跟随，请确认桌宠已显示、跟随规则允许该来源，并结束动作试映。启动成功、连接数量和动作试映不能单独代表已收到真实会话事件。

## 5. 失败恢复

桌宠没启动也能运行：

```powershell
node bin/board-pet.js doctor
node bin/board-pet.js settings
```

第一条显示版本、Node 环境、数据目录、连接情况及运行时准备错误，第二条重试启动并打开工作台。诊断命令不会启动桌宠或修改代理配置。

- **下载失败／连接拒绝**：检查网络、系统和启动宿主继承的代理变量，确认代理服务与端口相符，修复后重新启动。无需删除用户配置。
- **权限或磁盘错误**：检查诊断输出的数据目录是否可写、磁盘空间及安全软件拦截记录。
- **准备中**：等待同一用户的首次下载完成后重试，避免反复安装。
- **已启动但没有真实事件**：确认插件启用，Node 在 PATH 中，Codex Hooks 已审核；Cursor 重载窗口，DSH 检查 profile；结束试映、改成对应来源自动跟随，再开新会话发送消息。
- **仍然失败**：保留诊断输出；若工作台能打开，在「应用设置 → 版本与诊断」查看并导出诊断。分享前检查其中的本机路径；不要分享带访问凭证的本地控制页面地址。

网站下载区出现「获取失败」时可直接重试；仅成功查询且未配置发布包时才显示「待发布」。
