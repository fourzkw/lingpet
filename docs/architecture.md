# 灵伴桌宠架构（0.6.2）

DSH 插件监听 session/event 和 agent 生命周期；Cursor 与 Codex 通过各自 Hook 和本机桥接归一化事件。三种来源共用 BridgeClient，将白名单元数据传给本机桌宠。监听回调只做同步映射与入队，不等待网络或动画。断线队列每个会话只保留最新状态，总量有上限；重连后发送已观察会话的当前状态，不重播历史庆祝。

每种 Hook 桥接使用用户数据目录内的独占服务锁，避免并发冷启动建立多个持久服务。BridgeClient 重复 start 不增加心跳定时器，同一时刻只运行一个 flush；close 禁止新事件入队，并等待进行中的注册、请求和运行时准备完成后再注销来源。主服务 close 可重复调用；旧服务退出时仅删除与自身凭证匹配的 endpoint，不删除新服务发布的连接信息。本机通道仅监听 127.0.0.1，要求随机凭证并拒绝浏览器 Origin；受限环境的 EACCES 需与程序断连区分。

桌宠Electron主进程持有唯一StateStore及本机认证HTTP服务，渲染窗口只拿快照。主进程以用户目录为single-instance命名空间，避免多个DSH实例重复启动桌宠。用户主动退出写入暂停标记，插件停止自动唤起，CLI显式启动解除暂停。

StateStore 以 (instanceId, sessionId) 区分来源，以单调事件序号去重，旧 turn 不能覆盖新 turn。PetRegistry 管理多只桌宠，各自保留外观、显示版本、位置、大小与跟随规则。resolveFollow 按全局、来源或固定会话为各桌宠选取状态；固定会话用 source、scopeId、sessionId 在桥接重连后继续识别。等待批准／提问优先；完成为单次瞬态；失去心跳后显示 offline。

运行时优先复用本包已准备的Electron发行文件，否则下载到用户目录并校验官方随包SHA256。DSH Electron Host运行在Node模式，启动子进程时清除ELECTRON_RUN_AS_NODE，避免桌宠被作为纯Node程序执行。

桌宠渲染依赖角色资源与统一状态。Claude 使用 actions-v2 独立姿势帧；当前 DeepSeek 鲸鱼娘、ChatGPT 云羽龙姬和白羽龙姬使用视频处理得到的动作图集，支持原图／像素版本。动作按 manifest 的帧时长、单次进入与循环区间播放；支持同一状态多个候选动作。点击和摸头优先使用专属素材，无专属素材时使用通用回应；互动只覆盖本地播放，真实会话状态变化立即接管。旧版状态图与 16/32 点阵素材保留为历史资源，设备连接尚未实现。

SettingsStore 对 settings.json 进行 JSON 与配置结构验证，串行保存不可变快照，并以临时文件加 rename 发布。有效变更前保存上一份有效配置至 settings.json.bak；重复保存不轮换备份。启动时配置损坏或丢失则恢复有效备份；两份均损坏时分别保留原文后使用默认设置。权限、磁盘等 I/O 异常不按配置损坏处理。恢复会自动打开工作台；应用设置提供恢复结果、手动恢复和配置目录入口，手动恢复前保留当前文件。Windows 开机启动通过系统登录项注册；应用更新支持本地解压目录，尚无应用本体远程版本检查。

插件停用只注销其来源，不关闭其他插件共用的桌宠。暂不增加系统服务、管理权限或模型API依赖。

DSH浏览器端通过包的 `dsh.client` 声明加载 `client/client.js`，仅向 `settings.section` 注册一个桌宠页，不注册侧栏项。页面读取 `configForms` 的 `board-ai-pet` 命名空间，写入沿用DSH原生修订号、只读检查与profile持久化。Host将自动启动和子Agent选项声明为volatile引用，每次操作读取最新值；其他普通配置仍通过配置文件修改。页面停用或HMR卸载时注销注册项，避免重复入口。

设置页的启停按钮走宿主插件在DSH Web服务器注册的 `/board-pet` 前缀路由：`GET /board-pet/status` 读endpoint并探测 `/health`，`POST /board-pet/start|stop|dashboard` 分别显式启动、请求桌宠 `/quit`、打开工作台。路由只接受同源请求，POST还要求 `x-board-pet: 1` 头（跨源浏览器请求会先被CORS预检挡住）；桌宠本机服务仍拒绝浏览器来源并校验64位token，所以这条通道始终是Node到Node。停止复用托盘的暂停标记：写 `runtime.paused` 后退出，插件的自动唤起随即停止，直到用户再次显式启动。

热更新由DSH HMR负责插件的卸载与重新挂载。Symbol.for与按DSH根Context索引的WeakMap保存来源ID和单调序号；卸载延迟1500ms发送断开通知，快速重载会取消旧通知。真正停用仍会断开，长时间卸载后重新安装会建立新来源。挂载时从DSH重新读取活跃会话，不缓存或重播会话正文。

BridgeClient连接本机服务后比较包内容摘要，通过认证的 `/runtime/update` 提交当前插件包目录。桌宠验证包名、绝对路径与内容，再区分界面刷新或原生主进程替换；忽略较低版本请求。摘要相同不重复加载。页面更新先等待初始窗口加载完成，避免并发加载中断。

主进程替换时先保存设置和短期状态快照，再通过Electron relaunch启动新版入口，仅退出桌宠。新进程读取30秒内的快照，完成状态归为空闲，避免重复庆祝；插件自动重连并补发当前状态。快照只包含原有白名单元数据，更新不终止DSH或Agent回合。0.1.0原生桌宠没有更新接口，首次迁移需手动重新启动桌宠一次。
