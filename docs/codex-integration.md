# Codex 接入

先按 [快速开始](getting-started.md) 安装 Windows 桌面版，再通过灵伴工作台管理接入。灵伴的 Hook 和 MCP 入口使用安装包携带的运行环境，无需为灵伴另外安装系统 Node.js。

## 安装与验证

1. 确认本机已安装并能运行 Codex CLI。灵伴会用它注册本地接入；未检测到时，可在高级选项中指定已有命令位置。
2. 在灵伴工作台「Agent 接入」选择 Codex，检查配置位置是否对应正在使用的环境。默认读取 `CODEX_HOME`，未设置时使用用户目录下的 `.codex`。
3. 点击「安装接入插件」，阅读完成弹窗中的后续操作。
4. 完全退出并重新打开 Codex，确认插件启用，按宿主提示审核并允许灵伴 Hooks。审核需由用户在宿主完成。
5. 新建会话并发送一条消息，在灵伴接入页确认收到真实会话事件。
6. 选择桌宠，在「跟随」页选择「仅跟随 Codex」或「自动跟随所有来源」；若在动作试映，点击「恢复实时动作」。

仅显示「已安装」或管理通道已连接时，尚不能确认 Hooks 已派发事件。接入成功以真实会话事件为准。

## 更新和故障排查

本体升级后会按接入内容变化更新已有托管接入，仍需按提示重开宿主或重新审核 Hooks。接入页提供「检查」「更新接入」和「重新安装接入」，操作只针对灵伴接入，不升级 Codex。

未收到事件时，依次检查配置位置、插件启用状态、Hooks 审核和宿主是否已完全重启，然后新建会话测试。若存在旧版完整插件，请先停用或卸载，避免与当前轻量接入并存。

从系统托盘退出灵伴后，Hook 不会重新拉起本体。请从桌面或开始菜单启动灵伴，再验证连接。只关闭工作台窗口时，后台与桌宠继续运行。

## 适用范围

接入面向同一台 Windows 电脑、同一用户的本机会话。WSL、容器、远程主机和云端环境不会自动连接本机桌宠。支持的状态取决于宿主实际派发的事件，动作试映不能用于验证真实接入。

接入位置、操作备份与自动更新说明见 [安装与接入管理](desktop-installation.md#agent-接入与更新)；诊断和反馈步骤见 [快速开始](getting-started.md#5-日常使用与排查)。
