# 灵伴 · Cursor 侧边栏

0.2.0 新增独立桌宠列表、新增/启用/暂停和定向工作台入口。所有桌宠由共享运行时管理，每只可单独选择形象及全局、DSH、Cursor、指定会话跟随规则。与 DSH 同装时共用一个服务；停用最后一个 Cursor 扩展窗口后只断开 Cursor 来源，保留 DSH 和共享服务。完整说明见项目 docs/multi-pet.md。

安装 VSIX 后，活动栏出现“灵伴桌宠”图标，可打开/关闭桌宠、打开工作台、刷新状态。命令面板也提供“灵伴：打开桌宠 / 关闭桌宠 / 打开工作台 / 刷新状态”。

关闭桌宠复用原托盘退出行为，暂停 DSH/Cursor 自动唤起；打开桌宠显式解除暂停。侧边栏与 Hooks 接入分开显示，未开始 Agent 会话时会显示“已注册，等待会话事件”，不将其误报为已连接。

扩展在本机 UI 扩展宿主运行，控制请求只由 Node 发送；Webview 无法访问端点令牌或直接请求本机服务。随包包含原生 Cursor 插件、桌宠运行时和角色素材。支持时通过 Cursor registerPath API 注册 Hooks；当前 3.24.12 未导出该 API，自动复用或安装 `~/.cursor/plugins/local/board-pet`，并合并用户级 Hooks 作为直接接入路径。修改用户 Hooks 前保留备份，只替换指向自身脚本的配置，保留其他策略。无需单独安装 DSH。首次安装后如未出现图标，请执行 Developer: Reload Window，再从活动栏“…”中查找“灵伴桌宠”。

0.1.1 修复 Windows Cursor PowerShell 管道向标准输入添加 UTF-8 BOM 导致的 JSON 解析失败；失败诊断只记录阶段及错误类型，不记录正文。已使用用户真实 Cursor 对话确认接收到会话。

Windows x64 本地构建包，未发布到扩展市场。Hooks 脚本仍需要 PATH 中的 Node.js >=22.19；管理按钮由扩展宿主直接调用，不依赖终端中的 Node。
