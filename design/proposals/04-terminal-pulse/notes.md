# 方向 D · 终端脉动 / TERMINAL PULSE

> 设计板：`design/proposals/04-terminal-pulse/board.png`（1600 × 4963）
> Token：`design/proposals/04-terminal-pulse/tokens.json`
> 生成脚本：`node design/proposals/04-terminal-pulse/board.mjs`

---

## 1. 一句话主张

**把桌宠做成一个可爱的 CLI 进程**：状态胶囊就是 statusline，动作就是进度条与行内提示，会话跟随是一个常驻的 `agent` 标签页。

不假装自己是消费级 App。目标用户一天 10 小时盯着终端和编辑器，所以这套视觉不去争「谁更萌」，而是把陪伴塞进开发者本来就舒服的审美里：近黑冷调、等宽标签、克制的荧光、所有装饰都对应真实信息。

## 2. 关键词

`终端` · `等宽` · `状态行` · `低饱和` · `克制的荧光` · `行号即信息`

## 3. 为什么适合灵伴

1. **灵伴的第一现场就是开发者的窗口边角。** 产品不占主屏，桌宠是「旁边那个东西」。终端/编辑器的视觉语汇天生适合这种「存在但不打扰」的位置，比卡片化、拟物化更省注意力。
2. **灵伴的真实数据结构本来就是「进程 + 会话 + 状态」。** 现有实现里桌宠挂在会话上（`cursor-task`、`dsh-main`），状态有 8 个、切换频繁。用 statusline 隐喻表达这套状态，等于让视觉结构等于数据结构，不需要发明装饰。
3. **开发者对「装」极度敏感。** 这套方案里没有一个装饰是凭空的：行号=会话序号，进度段=任务耗时，时间戳=真实时刻，元信息全是可核对的值。可信度本身就是审美。
4. **和现有暖桃色 SaaS 风格形成清晰的方向差。** 现状 7 个样式表 139 个 hex、19 档圆角（见 `design/audit/tokens.md`），这套方案把它收敛到 7 个色阶 + 1 个强调色 + 一个圆角档位（0/2），是四个方向里**最像工程系统、也最容易落地**的一版。
5. **不牺牲可爱。** 角色贴图就是像素鲸鱼娘，状态色和呼吸点负责情绪，荧光只做强调。可爱来自角色和动作，不来自圆角卡片和渐变。

## 4. 视觉系统

### 4.1 色彩

近黑冷调底，中性灰阶承担 90% 的面积，荧光绿只占 ≤8%。

| --- | --- | --- |
| 空闲 idle | `#8DA096` | 中性灰，不争注意力 |
| 思考中 thinking | `#79B8FF` | 冷蓝，脑力活动 |
| 执行工具 working | `#54F0A6` | 荧光绿，唯一「正在跑」的颜色 |

### 4.2 字体与字阶

系统字体，不联网：`Microsoft YaHei` 承担中文与标题，`Consolas` 承担等宽。**中文正文永远不用等宽**——等宽中文字距过宽、行气断裂，是这个方向最大的坑。

| 档 | size | weight | line-height | 字体 | 用途 |
| --- | --- | --- | --- | --- | --- |
| display | 40 | 700 | 1.05 | YaHei | 品牌 / Hero |
| h1 | 26 | 700 | 1.15 | YaHei | 页面主标题（桌宠工作台） |
| h2 | 17 | 600 | 1.2 | YaHei | 区块标题（你的会话伙伴） |
| body | 13 | 400 | 1.55 | YaHei | 正文、说明句 |
| meta | 11 | 400 | 1.4 | YaHei | 元信息、行内提示 |
| mono | 10 | 400 | 1.4 | Consolas | 代码、路径、快捷键、数字 |
| micro | 8.5 | 500 | 1.2 | Consolas | 角标、状态标签、时间戳 |

等宽文字一律加字距 0（不额外拉开），标签用方括号 `[working]` 表示「这是一个机器态」，中文状态词永远跟在方括号外面。

### 4.3 形状与描边

**圆角只有 0 和 2 两个值。**

- `0px`：状态块、进度分段、任务栏、键帽底、图标盒。
- `2px`：窗口、面板、卡片、控件、胶囊（胶囊感靠左右内边距，不靠半圆）。
- 描边一律 `1px`，只用 `--lp-line` / `--lp-line-strong` 两级灰；不用阴影做层次（暗色下阴影几乎不可见，会脏）。
- 分隔线 `1px`，横向贯穿，不缩进；表格式布局用「列对齐 + 1px 分隔」代替卡片套卡片。

### 4.4 光影与纹理

- **面板阴影**：`0 16px 48px rgba(0,0,0,.55)`，只给浮层（菜单、拖动条），窗口本体不用。
- **荧光辉光**：`0 0 18px rgba(84,240,166,.45)`，只给角色周围的地面反光与主按钮 hover，半径 ≤48px，贴着角色走。
- **纹理**：点阵 `dot 18px`（桌面壁纸）、扫描线 `scan 1px/4px`（仅两处：壁纸与拖拽条，缓慢下移）、斜线 hatch（空状态卡）。纹理都做在 4~6% 不透明度，只做「有材质」的暗示，不做壁纸。
- **接触阴影**：每个角色脚下一枚压扁椭圆（`rx≈0.3×角色宽`，opacity .55~.62，blur 2px），保证角色「踩在桌面上」而不是贴上去。

### 4.5 动效

| 动效 | duration | easing | 触发 |
| --- | --- | --- | --- |
| 状态切换 | 160ms | `cubic-bezier(.2,.8,.2,1)` | 行内刷新闪一下 + 胶囊底色 steps(8) |
| 气泡出现 | 160ms | ease | 尾巴 90ms 先出，正文 70ms 后淡入 |
| hover 反馈 | 90ms | linear | 描边变亮 + 背景 +4% 亮度 |
| 光晕呼吸 | 3.2s | ease-in-out infinite | 只动 `opacity`（.14 ↔ .26），不动 alpha 以外属性 |
| 扫描线 | 8s | linear infinite | 壁纸、拖拽条（两处） |
| 光标闪烁 | 1s | `steps(2)` | 输入 / 等待输入态 |
| 进度条 | `steps(8, end)` | — | 不用线性插值，保留「跳格」的终端手感 |

`prefers-reduced-motion: reduce` 下所有 duration → 0ms，仅保留颜色 / 可见性切换；`prefers-color-scheme: light` 切浅色变体；`--lp-accent` 可被宿主覆盖。

### 4.6 图标与图形

一切图标用「几何路径 + 符号」两套：

- **符号**（Consolas / Segoe UI Symbol）：`◐ ◇ ✓ ✕ ⌛ ▮ ▸ ⏎ ⇄ ⚙ ↑ ↓ ⌫`，全部在 16px 下测过可辨识；`⌘` 一律换成 `Ctrl`（Consolas 栈下 `⌘` 会回退成 CJK 字形，实测会显示成方块字）。
- **几何**（自绘 16×16，`stroke=1.5`）：8 个状态图标 = 圆圈+点（空闲）/ 三点（思考）/ 三柱（执行）/ 光标+下划线（等待输入）/ 方框+感叹号（等待确认）/ 对勾（完成）/ 叉（错误）/ 月牙（休眠）。形状差异先于颜色差异，色盲用户也能读。

## 5. 各表面设计要点

### 5.1 桌宠浮层（512 × 512 透明窗）

- 窗口本身没有底色，只有三块 UI 面：**状态胶囊**（顶）、**互动气泡**（侧）、**hover 操作条**（顶，悬浮才出）。
- 状态胶囊 = statusline：`[done] 完成 · cursor-task · 3 处改动 · 00:42`。左边 4px 状态色条是唯一「重」的地方。
- 胶囊与气泡都贴角色：胶囊在头顶 20~30px，气泡在角色头侧、尾巴指向角色。角色底部接触阴影 + 地面反光让透明窗有「落点」。
- 透明窗口契约：只有角色与控件有像素；虚化背景与任务栏属于宿主桌面，不参与透明层。辉光半径 ≤48px，避免 512 窗口出现矩形边界。

### 5.2 快捷控制（右键弹层，340px）

- 340px 是所有元素宽度倒推出来的：`Claude · 像素 · 已显示` 不折行，再宽就抢桌面。
- 四只桌宠一行一只：32px 缩略图 + 名称 + `引擎 · 形象 · 显示态`，当前项加左侧 2px 荧光条 + 7% 荧光底，右侧标 `▮ 当前` / `● 显示` / `○ 隐藏` 三态。
- 显示桌宠（`Ctrl+H`）、大小三档滑杆（`中 · 192px`）、会话跟随（显示当前会话 id + `跟随中`）三段，底部实心/描边主按钮 `进入工作台 ⏎`。
- 底部一行 `↑↓ 切换 · ⏎ 确认 · esc 关闭`：键盘可达，不依赖鼠标。滚动暗示用 2px 轨道 + 滑块。

### 5.3 工作台（1472 × 912 窗口）

- 左侧栏 316px：品牌（`灵` 方块 + 灵伴 + `LINGPET v0.9.4`）、导航 2 项、我的桌宠 4 项（缩略图 / 名称 / `Claude · 像素 · 已显示` / 删除控件）、底部 `+ 新增桌宠` 与两行小字提示。
- 主区标题 `桌宠工作台` 26px + 副标题，右上连接胶囊 `● Codex / Cursor / DSH 已连接 · 3`。
- 实时预览：白色以外的所有内容都在 512² 舞台里，底部状态胶囊、会话行、`隐藏桌宠`（描边按钮：绿框 + 深底 + 绿字，破坏性动作不占主行动的荧光实心位）、`预热形象缓存 2/3` 后台任务条。**加载态放在真实后台任务上**，而不是给已加载好的角色硬加骨架屏。
- 设置卡：tabs `外观与显示` / `会话跟随`，选择角色 3 卡（DeepSeek 选中）、选择形象（`已保存` 徽章 + `原图 / 像素` + `+ 导入本地包` 空状态）、大小滑杆、三个开关、底部 `# config.json · 修改后 0.2s 自动保存`。**开关只有一种画法**：同尺寸轨道 + 12px 方钮，`on = 荧光淡底 + 荧光描边 + 荧光方钮（贴右）`，`off = 画布底 + 中性灰描边 + 中性灰方钮（贴左）`，两态只换 token，不换结构。
- 底部两条：`FOLLOWED SESSIONS / 会话跟随记录`（3 条，含 `● 跟随中 / ○ 已暂停`）与 `KEYBOARD / 快捷键`。

### 5.4 市场（lingpet.market）

- 卡片是主角：340 × 216，封面 118px 高，点阵 + 椭圆光 + 角色 100px，底部名称 / `by 作者` / `↓ 12.4k` / `+ 安装`。
- 悬停态（第二张卡）用 1px 荧光边框 + 8% 荧光底，不用放大位移。
- 顶部搜索框（`Ctrl+K` 聚焦）、`+ 导入本地包`、3 个 tab、右侧 `安装方式：默认桌宠 ▾`（下拉与工作台状态同源）。
- 结果条 `共 4 个结果 · 按热度排序 ▾ · 仅显示已适配 DSH 0.9+`。

### 5.5 DSH 设置面板

- 460px 宽深色卡：`设置 / DSH · 插件`、`你的会话伙伴`、运行状态卡（`● 运行中` + `cursor-task · 04:12 已用` + `v0.9.4`）、3 个 checkbox 行（`打开工作台` / `会话偏好` / `恢复继承配置`）、实心主按钮。
- 底色必须由 `color-mix(in srgb, currentColor 6%, #070A09)` 派生，这样宿主换主题时面板跟着走，不写死 hex；强调色可被 `--lp-accent` 覆盖。
- 浅色变体是同一套结构的另一种密度：`#F3F7F2` 底、`#0E9B63` accent、`打开工作台` + `取消` 双按钮，右侧列出 4 个关键 token 的 hex。

### 5.6 市场网站

- 同一套 token 的「网页密度」：站点 chrome + 导航 + hero（`把陪伴装进浏览器里`）+ 本周热门 + 3 张卡 + footer。
- 与客户端共享 CSS 变量：站点、面板、桌宠窗三层同一数字；差异只在排版密度（网站 body 15→13、卡片 340→192）。

## 6. 状态与动效清单（8 态 × 视觉表现）

| 状态 | 胶囊文案 | 颜色 | 形状 / 图标 | 动效 | 附属信息 |
| --- | --- | --- | --- | --- | --- |
| 空闲 | `[idle] 空闲` | `#8DA096` | ○ 圆圈+点 | 无动效（保持安静） | 会话列表、上次活跃 |
| 思考中 | `[thinking] 思考中` | `#79B8FF` | 三点 | ASCII 转轮 1.2s + 呼吸点错相位 | 正在读的文件 |

| 等待输入 | `[input] 等待输入` | `#E8D44D` | 光标+下划线 | 1s steps(2) 光标闪烁 | 待填的字段 |
| 等待确认 | `[approval] 等待确认` | `#E8A33B` | 方框+感叹号 | 虚线框流向 1s + 键帽出口 | 待执行命令、`等待 00:12 / 超时 60s` |
| 完成 | `[done] 完成` | `#4FD8E8` | 对勾 | 160ms 行内刷新闪一下 | `3 处改动 · 2 个文件`、`00:42` |
| 错误 | `[error] 错误` | `#FF5F66` | 叉 | 反色行 40ms 抖动 + 直接摊开日志 | `exit 1`、`at pet.ts:88`、可恢复性 |
| 休眠 | `[sleep] 休眠` | `#5F7379` | 月牙 | 光晕呼吸降到 .14 | 下次唤醒条件 |

每个状态至少有两维差异：**颜色 + 形状**（图标）+ **附属信息**（会话/耗时/文件数），动效只做第三维强化，不做唯一区分手段。

### 7.2 CSS 变量表（3 行示例，完整见 tokens.json）

```css
--lp-bg: tokens.colors.bg;                          /* #070A09 */
--lp-state-working: tokens.colors.state.working;     /* #54F0A6 */
--lp-base: tokens.motion.easing;                     /* cubic-bezier(.2,.8,.2,1) */
```

前缀统一 `--lp-`，分组：`--lp-bg/surface/surface-alt`、`--lp-line/line-strong`、`--lp-text/text-muted/text-faint`、`--lp-accent/accent-soft/accent-text`、`--lp-state-*`、`--lp-r-*`、`--lp-shadow-*`、`--lp-dur-*`、`--lp-ease`。

### 7.3 新增类

- 状态：`.lp-chip`（胶囊）/`.lp-chip-seg`（4px 色条）/`.lp-chip-state`（`[done]` 等宽）/`.lp-chip-note`（中文）/`.lp-chip-meta`（右侧数字）。
- 排版：`.lp-mono`（Consolas 10px/1.4）、`.lp-micro`（8.5px/500）、`.lp-label`（方括号标签）。
- 结构：`.lp-panel`（1px 描边 + 2px 圆角）、`.lp-row`（48px 行高，含 `.is-current`）、`.lp-seg`（分段进度）、`.lp-keycap`（键帽）、`.lp-scan`（扫描线纹理）、`.lp-dots`（点阵）。
- 状态属性：`[data-lp-state="thinking|working|…"]` 驱动 `--lp-state`，组件只读一个变量，避免 8 套选择器。

### 7.4 性能注意

- 全部动效只用 `opacity` / `transform` / `background-position`；不使用 `box-shadow` 动画、不使用 `filter: blur` 动画（Electron 透明窗下 blur 会掉帧）。
- 扫描线用 `background-position` 位移（1px 步进），并限制在 2 个元素上；`prefers-reduced-motion` 直接 `animation: none`。
- 像素贴图加 `image-rendering: pixelated`，512 窗内不缩放；桌面宠窗不做 backdrop-filter（透明窗 + 模糊在 Windows 上代价高）。
- 状态胶囊更新走 `requestAnimationFrame` 合批，避免每帧重建 DOM；进度条宽度用 `transform: scaleX()` 而不是改 `width`。

## 8. 取舍与风险

1. **等宽中文可读性差** → 硬规则：等宽只做标签 / 元信息 / 代码，中文正文一律 Microsoft YaHei；等宽字号最低 8.5px，且只出现在低信息密度位置。
2. **「黑客电影绿」廉价** → 荧光绿只占画面 ≤8%（板面实测约 7.4%），其余全部交给中性灰阶；绿色只出现在「正在运行 / 焦点 / 主按钮」，其它状态各有自己的色，避免整屏一色。
3. **全屏暗色容易闷** → 用 1~2 处高对比荧光做呼吸（主按钮、进度段、角色地面反光），并用等宽大标题（40px）+ 留白制造节奏，不靠渐变堆气氛。
4. **开发者觉得「装」** → 一切装饰必须对应真实信息：行号槽=会话序号、进度段=任务耗时、时间戳=真实时间、`8.5px` 元信息=可核对的值。板面上没有纯装饰图形（点阵/扫描线是「桌面材质」，且只做 4~6% 透明度）。
5. **本方向不适合的人群**：非开发者、把桌宠当陪伴玩具的用户、需要强情感表达的场合。这些人是方向 A（暖色卡通）与方向 C（手绘）的主场，不该由 D 覆盖。
6. **像素素材在 1.17× 缩放时会轻微失真**：落地时必须按素材内容 bbox 对齐（本板已按 alpha bbox 对齐接触阴影），或固定 1× / 2× 整数倍，不要任意缩放。

## 9. 不适用场景

- **消费级市场首页 / 拉新落地页**：终端审美对非开发者是「门槛感」，拉新页面应用暖色方向。
- **需要强情绪表达的陪伴场景**（节日活动、角色生日、养成玩法）：这套语言克制，情绪浓度不够，活动页应叠加 A/C 方向的表达层。
- **浅色系统主题为主的环境**：虽然给了浅色变体，但本方向的辨识度建立在暗色低饱和上；若宿主强制浅色，应回退到 A 方向的浅色版本，而不是把这一套硬拉到浅底。
- **展示型大屏 / 海报**：1600 宽板是评审用的，实际界面密度高；大屏应向 06 节取「大字号 + 稀疏信息」的版本，不能直接放大。
