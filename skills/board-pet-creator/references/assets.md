# 桌宠资源与实际验证

## 名词和形象组织

- **用户参考图**：用于身份、画风或姿势，不一定是动画首帧。
- **基础立绘**：本次确定并用于生成视频的形象。
- **原图版**：保留生成视频细节与平滑透明边缘的动画帧，不表示直接播放用户上传的人物原图。
- **像素版**：对同一形象的视频帧统一像素化后的版本。

组织为 `角色 → 多个形象 → 每个形象实际拥有的版本`。原图和像素版是同一形象的显示版本，不应增加两个角色分类。某形象只有像素素材时不能把放大像素图宣称为新的非像素原图。

## 后处理

保留原始生成视频，另存处理结果和预览。根据素材实际背景选择透明输出或抠像方案。绿幕不适合包含需保留的绿色细节的角色；不要无条件删除全画面绿色，先检查服饰、饰品和特效。

清除背景溢色和低透明度边缘色斑。不能仅因 PNG 支持 alpha 就认定已正确抠像；在深、浅背景上检查。清理碎片时保护独立的尾巴、饰品、道具和用户要求的小伙伴。

原图版保留颜色细节和平滑 alpha。像素版按形象建立共享色板，避免逐帧自适应调色造成闪烁；使用明确的像素网格与所需透明度，显示放大采用最近邻。两版使用一致构图和对应动作时序。

保持统一人物尺度和基线，避免逐帧自动裁切缩放造成呼吸式放大缩小。重采样视频时记录真实帧时间，时长由时间戳/帧率推导，不只用图集帧数猜测。

局部稳定或腿部锚定仅在有必要且符合动作时使用：从当前已确定参考图推导区域，允许角色/动作分别配置，保持道具前后遮挡，检查裙摆和身体衔接。不要复制其他角色的固定坐标或把真实走路/跳跃的腿锁住。

## 当前播放器格式

目标播放器或插件工具声明的资源格式优先。当前项目的视频图集常用本地 `manifest.json` 和等价的 `manifest.js` 模块，后者适应禁止 `fetch` 的桌宠页面；不要为了读取清单放宽页面网络安全策略。

当前字段含义：

| 字段 | 含义 |
|---|---|
| `schemaVersion` | 清单版本 |
| `character` | 资源/素材标识；不要与角色分类 ID 混淆 |
| `tileSize`, `columns` | 单帧尺寸、每行格数 |
| `clips[state].file` | 相对图集路径 |
| `sourceFrames` | 图集内实际源帧数量 |
| `frames` | 播放序列中的源帧下标，可重复引用 |
| `durations` | 与播放序列等长的逐帧毫秒数 |
| `loop` | 持续循环或单次播放后保持末帧 |
| `loopFrom` | 持续循环开始的播放序列位置，不是源帧下标 |
| `alternatives` | 同一状态额外的完整 clip 对象，最多7套，不允许嵌套 |
| `selection` | 主 clip 上的 random 或 round-robin；省略默认为 random |
| `original` | 原图版本的尺寸和相对目录等信息 |

本项目已有的实例是：192px 像素帧、384px 原图帧、8 列图集；124 帧源视频以约 12fps 采样得到 63 张源帧，持续段可以重复引用源帧。它们是现有实现参数，不是所有模型和桌宠都必须采用的标准。更换参数时要验证播放器兼容性。

多候选从灵伴 0.4.9 起支持。主 clip 保留原有字段，候选使用相同图集规格，帧数与时长可不同；同状态 loop 一致。分享包图集名称为 `sprites/idle.png`、`sprites/idle-1.png` 等，候选索引1至7，原图放在对应的 `original/` 下，`pet.json` 的 minAppVersion 为 `0.4.9`。播放器只加载当前需要的图集，完成状态的保持时长按最长候选计算。

## 验证与导入

至少检查：

1. 所需状态齐全，任务真正成功，产物与选定基础图版本对应。
2. 图集可解码，尺寸和下标合法，逐帧时长为正，循环起点有效。
3. 人物、附肢、道具不越界，基线与尺度稳定，背景清除且没有误删关键细节。
4. 身份、肢体连接和用户指定约束满足；例如脚向要求必须查看视频与最终输出，而不只检查提示词。
5. 眨眼自然；动作进入与持续段衔接合理；完成/异常不反复重演；睡眠不在循环时睁眼。
6. 原图版保留细节；像素版颜色和透明度稳定；两版都能真实播放。
7. 实际桌宠窗口中角色/形象/版本选择正确，切换不改变其他实例的跟随规则；原有形象仍可选择。

记录实际做过的检查及其限制。缺少目标播放器或导入工具时可交付资源和清单，明确尚未导入或激活，不能以静态预览代替“已安装运行”的结论。
