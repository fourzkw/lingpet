# 灵伴桌宠创作

在当前灵伴桌宠插件内完成对话式创作。用户可提供参考图和目标风格，也可只用文字描述；DeepSeek/GPT 负责理解需求和调度工具，实际图像、视频生成由已配置的后端执行。不要求另装一个桌宠插件或使用一键创作界面。

## 先确定执行条件

开始执行前阅读 [能力与环境](references/capabilities.md)，发现本次宿主实际暴露的工具，核对文件输入、图像生成、ComfyUI、任务查询/取消和资源导入能力。不要把本文中的操作意图当成已存在的工具名。

当前工具版本的真实名称、输入规则与调用顺序见 [创作工具](references/tools.md)。使用当前插件工具时先读取该文；旧安装版本未必已经提供这些能力。

使用 ComfyUI 时，[推荐模型配置](references/tools.md#推荐的-comfyui-模型配置) 列出已验证的 Qwen Image 2.1 / MiniMax H3 模型绑定。用户保存的配置优先；推荐文件名须经当前环境检测后使用。

Skill 本身不增加生成接口，不附带模型或 ComfyUI，也不保证宿主能读取本机路径。缺少执行能力时完成可做的设定和提示词整理，准确说明缺少哪一项；不要声称已经提交、生成或安装。

生成前调用 `board_pet_generation_settings {action:"inspect"}`，读取应用设置中的生图／视频服务、协议和各自优先级。默认通过插件生成工具的 `provider:"auto"` 遵循用户设置；用户明确指定服务时传对应 provider。当前宿主提供 ImageGen 工具时，调用生图工具传 `hostTools:["imagegen"]`，使 Codex ImageGen 按设置优先级参与选择；不可用时省略。返回 `provider:"imagegen",status:"requires_host_tool"` 时，按返回的提示词和参考图调用宿主 ImageGen，再通过 `add_reference` 导入结果并审阅、`select_base`。这是交接请求，不是已经生成成功或后台任务，不要轮询。用户明确指定 Codex ImageGen 时可传 `provider:"imagegen"`。具体参数、任务恢复和服务限制见 [生成服务与优先级](references/generation-services.md)。

不因加载 Skill 就自动启动任务。用户仅询问流程、提示词或创建 Skill 时，不生成素材。用户要求停止时，停止当前项目的调度及所属生成任务，保留产物和进度；之后讨论流程不构成恢复生成的授权。

## 创作流程

1. **建立或恢复项目。** 阅读 [项目记录](references/project-record.md)。收集身份特征、风格、比例、姿势、目标角色/形象及所需显示版本。优先从参考资料和上下文提取，仅询问影响结果的缺失信息。参考图用于人物身份、风格或姿势时分别标明其作用。
2. **形成基础图。** 阅读 [创作与检查](references/creation.md)，按文字或图片输入选择可用后端。将最终提交的提示词和参数写入项目，展示产物并检查轮廓、服饰、肢体和小尺寸辨识度。不要将多动作图集作为图生视频的首帧。
3. **确定采用的版本。** 默认先给用户一次造型反馈机会，再扩展长批次。用户已确定基础图或明确授权连续完成时不重复确认。修改基础图后使依赖旧版本的候选视频失效，避免混用旧形象。
4. **分析角色并设计动作。** 阅读 [创作与检查](references/creation.md) 的动作设计部分，从确定的形象、角色设定和用户偏好中提取可用特征，将状态语义转化为符合该角色的动作、道具及特效。先记录各动作的分镜、进入/持续/结束行为、目标时长和循环点；时长按内容决定，不统一套用约五秒。用户给出的动作构想优先，不强制所有角色使用键盘或同一套动作。
5. **试片并扩展。** 先制作一个能验证本次关键设计的样片；用户已指定动作时优先该动作，复杂持物或道具交互应先验证，简单形象可先试空闲。实际检查视频帧、肢体/道具接触和循环，修正明显问题后再扩展其余状态。所有动作使用同一确定版本的基础图、画幅和角色比例；按分镜分别设置合法帧数，已授权的批次可连续执行并记录进度。
6. **处理与导出。** 阅读 [资源与验证](references/assets.md)。抠像并清除溢色，分别导出保留细节的原图帧及需要的像素帧，建立动作时序和形象元数据。只创建用户要求的版本。
7. **接入并交付。** 新造型通常加入原角色下的形象列表。只有用户要求替换或切换现有实例时才更改其选择；保留其他形象、实例和跟随配置。真实验证后分别报告已生成、已验证、已导入、已激活哪些结果，并提供可预览的文件或资源链接。

## 执行约束

- 使用用户的后端配置与实际能力；不要假定聊天模型具备图像生成能力或共享当前 AI 的内置工具。
- 用户要求优先于默认样式。Q 版不等于固定坐姿或隐藏小腿；“不要内八”等要求保存为该项目约束并应用于后续图像、视频和检查。
- 不硬编码另一台机器的目录、模型文件、人物名字或身体修正坐标。需要兼容的模型和节点先检测，选用安装环境支持的工作流。
- 区分请求被接受和任务完成；检查执行历史及可读输出后才认定成功。中途更换视觉输入时使用新修订，不以旧文件存在作为新任务完成的证据。
- 只取消本项目明确拥有的任务；不清空公共队列或中断别人的任务。详情见 [能力与环境](references/capabilities.md)。
- 稳定下肢、局部合成等修正属于可选后处理；仅在符合角色、动作和用户要求时使用，记录处理范围，并复查接缝和道具遮挡。不能用统一固定区域覆盖全部角色。
